## Dashboard (CyberManager)

This repo includes a Dashboard UI for managing a cyber cafe (net shop) built with Next.js + Tailwind.

Setup environment variables in `.env.local` (copy from `.env.local.example`). The dashboard uses Supabase when `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are provided; otherwise it falls back to an in-browser mock stored in `localStorage` for development/demo.

Tables expected in Supabase:
- `may_tinh` (id, ten_may, trang_thai, tai_khoan_hien_tai)
- `dich_vu` (id, ten_dv, gia, so_luong_ton)
- `giao_dich` (id, machine_id, service_id, qty, started_at, ended_at, amount)

Run the app locally:
```
npm install
npm run dev
```

Deploy to Vercel: ensure the `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are set in Vercel env settings.

## Supabase schema and deployment guide

1) Create the tables on Supabase SQL Editor (copy and run):

```sql
-- Machines
CREATE TABLE IF NOT EXISTS may_tinh (
	id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	ten_may text NOT NULL,
	trang_thai text NOT NULL DEFAULT 'trong', -- 'trong', 'dang_su_dung', 'bao_tri'
	tai_khoan_hien_tai text
);

-- Accounts (users)
CREATE TABLE IF NOT EXISTS tai_khoan (
	id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	name text NOT NULL,
	email text NOT NULL UNIQUE,
	password text NOT NULL,
	phone text,
	balance integer DEFAULT 0,
	created_at timestamptz DEFAULT now()
);

-- Services (F&B)
CREATE TABLE IF NOT EXISTS dich_vu (
	id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	ten_dv text NOT NULL,
	gia integer NOT NULL,
	so_luong_ton integer DEFAULT 0
);

-- Transactions / Sessions
CREATE TABLE IF NOT EXISTS giao_dich (
	id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	machine_id bigint REFERENCES may_tinh(id),
	account_id bigint REFERENCES tai_khoan(id),
	service_id bigint REFERENCES dich_vu(id),
	qty integer DEFAULT 1,
	started_at timestamptz,
	ended_at timestamptz,
	amount integer DEFAULT 0,
	created_at timestamptz DEFAULT now()
);
```

2) Environment variables

Create `.env.local` with the values from your Supabase project settings (Project URL and Anon Key):

```
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
# Optional for server-side privileged actions (keep secret)
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```

3) Deploy to Vercel (step-by-step)
- Push your repo to GitHub.
- In Vercel dashboard, create a new Project and import your repo.
- In the Project > Settings > Environment Variables add the same keys used locally: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and if needed `SUPABASE_SERVICE_ROLE_KEY` (set as Protected).
- Deploy. Wait for build to finish. The app will use the environment variables at runtime.

Notes:
- Use the Supabase SQL editor to seed some `may_tinh` and `dich_vu` rows for demo.
- Keep the `SERVICE_ROLE` key secret; use it only on server-side functions (API routes) when performing privileged writes.
